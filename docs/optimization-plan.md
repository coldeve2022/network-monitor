# 网络监测软件系统修复与优化

目标：修复不可用功能、统一统计与交互、保留原有数据，并交付经过验证的 Windows 可执行程序。

实现路线：保留 Python/FastAPI/SQLite/ECharts。先修复数据和生命周期，再统一界面交互与自定义配置。逐项用回归测试和浏览器操作验证。功能扩展以可观察、可解释为准。

## 执行清单

- [x] 采集正确性：线程退出、同主机复用、路径取消、ICMP 报文匹配。
- [x] 数据正确性：首次目标初始化、离线样本、即时丢包率、重复目标、跨小时历史、迟到样本。
- [x] 配置可靠性：校验整批设置、原子写入、重启恢复、保存失败不假报成功。
- [x] 界面故障：丢包异常、标准差、主题、删目标残留、断开提示、重连快照。
- [x] 界面统一：统一面板与按钮、响应式排列、字号与密度、卡片显隐和图表宽度。
- [x] 实用扩展：本地诊断、历史窗口、CSV 导出、空状态和指标解释。
- [x] 交付验证：完整回归、桌面/窄屏浏览器、打包、保留原版程序与 dist/data。

## 验证重点

1. 全部无响应和部分无响应不能显示为健康，也不能被摘要忽略。
2. 同一个主机同时作为目标和路径跳出现时只发送一次物理探测，并保留路径位置。
3. 任意保存失败或非法参数不得部分更新设置或目标。
4. 关闭路径追踪、断开前端和退出程序后，不得再回填过期状态。
5. 旧版本的数据继续可读；现有错误历史不伪造为已修复。

## 已知统计边界

旧数据库没有每分钟样本数，历史摘要按聚合桶统计；新修复不能反推出旧版本错误的丢包记录。ICMP 无响应只能说明该探测无响应，不足以单独证明业务不可用。MOS 为经验估算，不是实际通话测评分数。
