## 数据正确性

- 部分/全部失败样本不再从健康状态与摘要中消失。
- 历史丢包按该分钟实际失败次数计算，避免对滚动丢包再平均。
- 分钟 min/max/std 基于实际 RTT；同主机重复行不再污染样本计数。
- 分钟充分统计信息与数据行在同一 SQLite 事务保存，可精确恢复新版跨重启统计；过期同步清理。
- 目标和设置使用先落盘、后更新运行状态，写入失败不假报成功。
- 30 天历史用小时表补足已清理的分钟数据，避免两者重叠。
- 原有数据库无样本数的记录保留并明确近似处理，不能修复已经丢失的原始数据。

## 交付边界与后续场景

这份结果表示已修复本轮发现且能够验证的问题，不表示软件从此没有任何 bug。AI 付费调用、长时间跨天运行、不同 Windows 权限环境、VPN 切换和大量目标压力尚未全面实测。

需要进一步产品定义的场景包括：按应用/游戏配置 TCP 与 DNS 目标、主动带宽测速、Wi-Fi 无线干扰诊断、逐进程流量、远程多机监测。它们需要额外的测量机制或权限，未用现有 ICMP 结果冒充。

运行设置保存为当前 exe 同级文件；界面偏好保存于当前浏览器，不同浏览器/端口的显示设置彼此独立。高延迟目标不一定异常，阈值需结合目标地理距离和业务要求解释。

## 2026-10-26 滑块拖动回归修复

用户反馈主图底部时间滑块不能拖动。真实持续采样下复现：左手柄拖动约 45% 图宽后，选区错误跳到全部历史。原因是主图强制 value rangeMode，在鼠标以百分比更新选区后，y 轴重算重新采用固定模式，导致选区重置。撤销显式模式锁定，保留两个缩放控件一致的绝对时间边界，由图表库随操作选择模式。

同时将主图选中区域设为整段可直接拖动，避免只能拖动细小移动条。新增 tests/slider_drag_browser.cjs，使用真实 Chrome 鼠标，验证慢速左手柄扩展、右手柄收窄、整段平移、实时刷新保持手动范围以及恢复跟随。旧代码在“拖动距离应对应正确范围”的断言下失败，修复后全部通过。26 项前端及 66 项后端回归通过。

图表库行为核对参照 [Apache ECharts DataZoomModel 源码](https://github.com/apache/echarts/blob/5.6.0/src/component/dataZoom/DataZoomModel.ts) 与 [SliderZoomView 源码](https://github.com/apache/echarts/blob/5.6.0/src/component/dataZoom/SliderZoomView.ts)。此前只检查选区有变化的浏览器断言不足，已补充拖动距离和左右边界的断言。
